## 0. 为什么 A0 必须先做(动机 / 它关闭的风险)

E1/E2/E4 三次都撞上**同一个根因**:复用 Isaac app 采集时,`reset(seed)` 不完全,留下**算子顺序物理残差**(#51/#52)。它把三处证据污染:

- **E1/A1 的 C2ST**:reused-app 下 matched O4↔O2 被时序判别器分到 0.85–1.0(假阳性);A1 用 fresh-app 修成 byte-identical,但代价是**一条车道一个进程**(慢)。
- **E2 的 Suite-Cal 闭环**:reach 数字不可复现(同 seed、仅顺序不同 → 0.00 vs 0.67)。
- **E4 的闭环左端点**:O10 floor=0.5 非单调掉点 + base 0.00↔1.00 翻转,均为顺序敏感噪声。

design-doc §2 把这些统一为 **A0.1**,并列为"单一剩余闭环阻塞"。同时,下游实验还缺三件预登记基础设施(R3/R4/R5/R7):一个**agent-无关的触发协议**(否则 A2–A6 的归因比较不公平)、一个**外观库 + 预登记 split**(否则 A2 会被"学了黄色→Backstep"的 shortcut 攻击打穿)、一个**成功判据 + 可行恢复集登记表**(否则 A4 的 attribution-gated correct-recovery 不是"预注册")。A0 一次性交付这五件,**每一件都被测试或在真实栈上验证**。

## 1. A0.1 —— 闭环确定性门。**判决:PASS(byte-identical + gold-match + validity-gate + 闭环顺序无关 + E4 dip/flip 消失)。**

### 1.1 Claim(服务 R1/R2 + 解锁 A0.3/A4/A6)
存在一个**确定性采集机制**,使同一 `(scenario, θ, seed)` 的本体轨迹**与采集顺序无关、逐字节可复现**,从而(a)E1/A1 的 C2ST 证书不再需要 fresh-app-per-lane 的慢路径、(b)A0.3 语料可在**单一复用 app** 内确定性采集、(c)A4/A6 的闭环数字可复现。

### 1.2 根因(Explore 侦察 + 首手代码,`isaac_policy_backend.py`)
`reset()` 只调 `_init_state()`(清 episode 标量 + `_resistance` 的内层标量),**不清**:(i)累积的算子 prim(`/World/{patch,collapse,wall,ridge,vplate,patchtex}_*` + `/World/Looks/patchtex_*`)—— **今天没有任何 despawn 路径**,它们跨车道堆积,改变 PhysX broadphase/warm-start **顺序**;(ii)region 容器 `_regions/_resistance/_collapse/_blocking/_support`;(iii)payload `_payload_kg`、effort `_effort_scale`;(iv)O2/O4 的外部 wrench buffer(`_apply_resistance_wrench` 在 `_resistance` 为空时 early-return,从不主动清零);(v)contact-sensor / articulation solver warm-start。**关键第二发现:matched 对 O4/O2 用 resistance region(无 prim),其残差主体是 wrench buffer + `_resistance` 堆积 + solver warm-start,不是 prim 堆积。**

### 1.3 修法(additive,部署 `reset` 一字未动 —— 红线)
新增 `IsaacPolicyBackend.deep_reset(seed)`(opt-in;部署路径 byte-identical):`_zero_external_wrench()` → `clear_payload()` → `set_effort_scale(1.0)` → `_despawn_operator_prims()`(按名字前缀删 `/World` 下全部算子 prim + reset `_n_patches`)→ 清空五个 region 容器 → flush contact sensor → 标准 `reset(seed)`(env.reset + teleport + settle 现在在干净地面上)。`run_episode`/`run_closed_loop` 加 `deep_reset: bool = False`(默认关 ⇒ walking skeleton + 所有既有 caller 逐字节不变;413 CPU 测试全绿证明无回归)。

### 1.4 头号发现:**几何也必须确定**(PhysX 浮点确定性依赖绝对坐标)
第一次跑 `deep_reset` 用**顺序索引的 y**(同 (op,seed) 在两 ordering 落在不同 y):cross-order max|Δ|≈**5–10** —— 貌似 deep_reset 失败。但这是**位置混淆**:flat 地面上 body-frame obs48 本应与 y 无关,Δ≈10 说明 **PhysX GPU solver 的浮点确定性依赖绝对坐标**(y=4 vs y=40 的舍入差,200 步内混沌放大)。**修法:每个 (scenario,seed) 用固定单车道 y**(deep_reset 已 despawn ⇒ 同车道顺序跑无空间重叠)。⇒ A0.1 修复是**两成分**:`deep_reset`(清状态)**+ 确定性单车道几何**(y=f(scenario) 而非采集序号)。

### 1.5 Results(`outputs/eval/a0/a0_1_certificate.{json,md}`;acceptance test)
`scripts/a0_1_determinism.py`(两 ordering、一复用 app)+ `scripts/a0_1_analysis.py`(离线 CPU):

| 机制 | 几何 | cross-order max\|Δ obs48⊕τ\| | 判决 |
|---|---|---|---|
| **deep** | **固定 y=4** | **0.0**(7/7 车道逐字节相同) | ✅ PASS |
| naive | 固定 y=4 | **19.81** | ✗(状态堆积 —— 证明清扫必要) |
| deep | 顺序索引 y | **10.59** | ✗(几何漂移 —— 证明固定几何必要) |
| fresh-app | 一进程一车道 | 0.0(A1 金标准) | ✅(gold) |

- **Gold-match(deep@固定y vs fresh-app 金标准,同 (op,seed)):7/7 车道 max|Δ|=0.0** ⇒ deep_reset **逐字节复现** fresh-app,不是自洽而已。
- **Same-op validity gate(deep,偶/奇 seed 结构化 C2ST,cnn1d):O4/O2,T∈{25,50} 全部 AUC=0.5、CI=[0.5,0.5]、perm_p=1.0、indistinguishable=True** ⇒ 无算子顺序残差可被利用(对比 A1 reused-app 结构化 same-op AUC 1.0/0.893)。
- **判决:`deep_cross_ordering_byte_identical=True, deep_reproduces_fresh_gold=True, same_op_gate_indistinguishable=True, A0_1_PASS=True`。**

### 1.6 闭环确认(E4 顺序敏感性签名)。**deep 使闭环顺序无关、E4 噪声签名消失;naive 复现 E4 混淆。**
`scripts/a0_1_closedloop.py`(`deep_reset=True` 装进 `run_closed_loop`,B1 + 部署 monitor,`a0_1_closedloop.json`):

| 机制 | O2_A iso vs after-O1(3 seeds) | O10 base grid(floor 0.9/0.7/0.5/0.4) |
|---|---|---|
| **deep** | **order-independent=True**(3/3 seed:iso==after,final_dist 全=0.597 逐字节相同) | **1.0 / 1.0 / 1.0 / 1.0**(稳定单调,**无 floor=0.5 dip、无 base 0.00↔1.00 翻转**) |
| naive | order-independent=**False**(iso≠after:d 0.597/0.599、2.505/1.039、2.653/3.264) | 0.0 / 0.0 / 0.0 / 0.0(残差污染,复现 E4 的 base=0.00 混淆) |

⇒ **A0.1 的闭环 acceptance 全部满足**(design-doc §2):(a)E4 reconcile 的 O2_A isolated-vs-after-O1 在 deep 下**逐字节一致**;(b)O10 floor=0.5 非单调 dip **消失**(0.5=1.0);(c)O10 base 0.00↔1.00 翻转**消失**(全 floor 稳定 1.0)。**附带红利:** deep 让 E4 苦寻的 **O10 闭环左端点干净出现**(base 全 floor reach 1.0),而 naive 残差把它污染成全 0.0 —— 这直接解锁 E4/A6 的 O10 轴。**红线守住:** θ 从不入任何 gate;deep_reset 只清物理残差。

### 1.7 How it supports the claim / 什么会证伪它
byte-identity 是比"AUC≈0.5"**更强**的确定性证明:任何本体函数对逐字节相同的输入必给相同输出。若 deep@固定y 的 cross-order Δ>0、或 gold-match Δ>0、或 same-op AUC≠0.5,claim 即被证伪 —— 三者都 =0/0.5。**吞吐红利:** deep_reset 在**单一复用 app** 内达成 byte-identity(无 per-lane app 重启),A0.3 语料因此可在 ~1 app 内确定性采集。

### 1.8 Honest scope
- **fresh-app 仍是"金标准"**;deep_reset 的价值是**在复用 app 内逐字节复现它**(已证),把 fresh-app 的慢路径变成快路径。二者对头号数字等价。
- deep_reset 是 opt-in 新方法;**部署 `reset` / loop / shield / spec 一字未改**(红线,与 A1 一致)。
- 几何必须固定:任何跨车道对比(C2ST、闭环)**必须**用 `y=f(scenario)`,不能用采集序号索引的 y —— 已写入 A0.3 采集器(固定 `lane_y=4.0`)。

## 5. A0.5 —— 成功判据 + 可行恢复集登记表。**R5 预登记、R4 冻结、与 taxonomy 交叉校验(反漂移)。**

### 5.1 Claim(服务 R4/R5/R6)
一个**先于任何 agent 评估提交**的 YAML,把"哪个恢复正确 / 什么算成功"钉死,独立于 agent 行为。头号指标(R6)= **attribution-gated correct-recovery**:归因对 ∧ 所选原语 ∈ **真因的** admissible 集。
