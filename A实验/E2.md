## 0. 结论速览(头号结果:匹配构造的 O4 冲突案例)

`matched_eval`:**30 个失效节点(15 个 O4-粘附冲突案例 + 15 个 O2-柔顺对照)**,每个 agent 开环单决策(归因 + 选原语),无 use_map / 无闭环路由 / 无 CBF。seeds 500–514(与 B5-conflict 训练用的 0–9 disjoint)。

**承重对比 —— O4 冲突案例**(本体说"泥地"、视觉说"线缆",必须压住本体信视觉)。指标 = **归因正确率** 与 **「正确恢复率」(联合、归因门控:归因正确 且 所选原语 ∈ 真因可行集)** —— 这是真正需要"理解原因"才能拿到的恢复数字。括号为 Wilson 95% CI(逐项独立快照,二项区间)。

| Agent | O4 归因正确率 (95% CI) | O4 正确恢复率 (95% CI) | 含义 |
|---|---|---|---|
| **B1**(最强纯本体) | **0.00 [0.00, 0.20]** | **0.00 [0.00, 0.20]** | 原则上不可能 —— 本体对匹配对完全盲(E1 C2ST≈0.50 背书,与训练无关) |
| **B5-unshaped**(只见过未整定 O4) | **0.27 [0.11, 0.52]** | **0.27 [0.11, 0.52]** | 有视觉(CLIP AUC=1.0 可分),但从没学过"矛盾时信谁"→ 多数答错 |
| **B5-conflict**(SFT 加 #49 匹配样本) | **1.00 [0.80, 1.00]** | **1.00 [0.80, 1.00]** | 学会了冲突消解 |

**严格单调且按 CI 显著:0.00 < 0.27 < 1.00。** B5-unshaped 上界 0.52 < B5-conflict 下界 0.80 ⇒ 中间行 < 最优行**显著**;B5-conflict 下界 0.80 ≫ B1 上界 0.20 ⇒ 正反两端**显著分开**。中间行 +0.73(0.27→1.00)就是冲突训练的净增益 —— **"有视觉通道 ≠ 会用视觉通道":冲突消解是一个学出来的语义操作**,不是数据覆盖副产品。这把 E1 的"匹配 OOD 困扰"变成了隔离这个确切操作的消融轴。

**为什么报「正确恢复率」而不是「可行恢复率」(关键呈现修正):** 原始 `feasible_recovery_rate` **不门控归因** —— 归因全错的 agent 也能蒙到一个恰好落在真因可行集里的原语,所以纯本体 B1 在它上面是 **0.567(非零!)**、B5-unshaped 是 0.933,这个数会掩盖归因失败,**不可上头条**。门控后的「正确恢复率」(归因对 ∧ 原语可行)把这层虚高去掉:**B1 0.00 / B5-unshaped 0.27 / B5-conflict 1.00**(逐项与归因正确率一致,因为这些 agent 的原语由归因经 canonical 映射导出)。原始 ungated 值保留在 `three_row.json` 作诊断,正是要规避的 footgun。

**O2 柔顺对照(非冲突,视觉与本体一致):** B1 0.00、B5-unshaped **0.87 [0.62, 0.96]**、B5-conflict 1.00 —— B5-unshaped 的视觉通道在"不矛盾"时几乎全对,**恰恰反衬**它在 O4 冲突案例(0.27)的失败是"不会用视觉压本体",而非"没视觉"。**总体(30 项)归因 0.00 / 0.57 / 1.00**(O4 冲突被 O2 对照抬高/稀释 —— 故头号是 O4 列,不是总体)。

**Suite-Cal(A 类)公允对照(见 §4 复现性披露):** 闭环 reach 数字不可稳定复现(E4 前置检查,`A实验/E4.md`),故"公允对手"论点改由两条**可复现**证据承载:**B1 未整定算子 0.764 归因保真度**(它是强归因器,不是稻草人)+ **E1 的 C2ST 上界**(纯本体在匹配对上原则上即 chance)。Suite-Sem 头号的开环三行(固定快照)确定、不受此影响。

## 1. 背景:为什么是三行,而不是两个 agent

E1 给了负面 airtight 证据(C2ST≈0.5:纯本体原则上分不开 O4↔O2)。但纯负面留了个窟窿:一个挑刺审稿人会说"你证明了纯本体不行,但没证明任何东西行 —— 也许这类失效就是不可恢复,而非'需要语义'"。这会把二分法降级成"有些失效对本体很难",而不是"有些失效需要语义"。

二分法真正的认知操作是**冲突消解**:当本体说"泥地"、视觉说"线缆"时,agent 能压住本体、信视觉。光证明"视觉里有信息"(可观测性,E1 CLIP AUC=1.0)不等于证明 agent 会用它。所以需要正面 demo:一个融合 agent 在匹配场景上成功。

而 #49 匹配构造对 B5(在未整定 O4 上训练)是 OOD —— 这不是麻烦,是礼物:它把"是否学过冲突消解"隔离成一根消融轴。于是三行:B1(纯本体,原则上不能)、B5-unshaped(有视觉但没学会用)、B5-conflict(学会了)。中间行是白捡的新论点。

判据(与 E1 同理):便宜、承重、该早做 —— 如果 B5-conflict 加了匹配数据后**仍然**失败(CLIP AUC=1.0 强烈暗示不会),正面命题就有麻烦,现在就知道。结果:B5-conflict 达到 1.00,正面命题成立。

## 2. 三个 agent(无策略重训框架,符合最小-agent 原则)

- **B1 —— 最强纯本体(训练的部分)**:RMA 式时序历史编码器(MonitorNet 1D-CNN+Perceiver)+ 12 类归因头,在**真实 Go2 全算子数据**上以 **window_len=50(1 s,RMA 典型)** 重训(`scripts/train_learned_monitor.py --window-len 50`,在已有监视器数据上,无需新采集)。留出集表现:**归因 0.764 / 检测 TPR_mean 0.977、TPR_min 0.915、FPR 0.050**(per-op TPR 全 ≥0.91)。→ **B1 是强归因器**(未整定算子上很准),所以它在匹配对上掉到 0 不是训练不足,是构造使然(E1 C2ST 上界背书)。`kino_vla/eval/proprio_baseline.py::ProprioBaselinePolicy` 把它包成一个 `VlaPolicy`(只读 proprio_window,忽略 RGB)。artifact:`outputs/eval/e2/b1_attributor/`。
- **B5-unshaped —— 既有视觉+本体 agent**:`outputs/vla/sft_latent`(Qwen3-VL-4B+LoRA+Kino-Projector,latent route),只在**未整定** O4(斜坡线缆 k≈150)上训过。
- **B5-conflict —— 加冲突训练**:同一 recipe(latent + nav 共训,epochs 4)+ 把 **20 个 #49 匹配样本**(matched-O4 黄板+泥地式 proprio → 标签 adhesion/Backstep;matched-O2 → compliant/Switch_Gait)并入 SFT 集(433 recovery + 525 nav,balanced 739 train)→ LoRA 重训(best_val 0.472,wall 712 s)。匹配样本的标签是特权已知,所以脚本化 CoT,无需 Oracle。artifact:`outputs/eval/e2/b5_conflict/`。

匹配样本里的冲突 CoT(matched-O4):"切向阻力像柔顺泥地,但表面是黄色粘附板 —— 信视觉而非本体:这是 adhesion,后退而非推过。"

## 3. 实验过程

1. **B1 重训**(window_len 50,真实 Go2 监视器数据,131920→123970 窗口)→ 0.764 归因 / 0.977 检测。`outputs/eval/e2/b1_attributor/`。
2. **匹配构造数据采集**(真实 Go2):`scripts/isaac_e2_collect.py` 驱动 matched-O4/O2,在监视器拦截处用 `SnapshotRecorder` 捕获快照(程序化黄/棕外观 + 匹配 proprio 窗口),附特权真标签 + 脚本化冲突 CoT,写成 `load_suite_sem`/SFT 格式。train 20(seeds 0–9 × 2 op)+ eval 30(15 O4 + 15 O2,seeds 500–514,与 train disjoint)。
3. **合并 + B5-conflict 重训**:既有 413 SFT + 20 匹配 = 433 → `outputs/eval/e2/sft_augmented` → `train_vla_sft.py`(同 B5 recipe)→ B5-conflict。
4. **三行开环评测**:`scripts/eval_e2_three_row.py`(无 Isaac;B1 CPU,两个 VLA GPU)在 n=30 matched_eval 上跑 `evaluate_attribution`,报**归因正确率 + 联合「正确恢复率」(归因门控)**(原始 ungated `feasible_recovery_rate` 仅作诊断)+ 逐算子 Wilson 95% CI。→ §0 的头号表(O4 冲突为承重列)。
5. **Suite-Cal parity**:`scripts/isaac_e2_cal.py`(真实 Go2)在 6 个 A 类场景 × 3 reps 上跑 B1/B5/B2 闭环 reach 成功率。

中途的诚实修正(记录在案):闭环匹配-O4 对 B5 是 OOD(它在未整定 O4 上训练)→ 把闭环 head-to-head 改成**开环单原语**(用户指令的三行设计),用归因准 + 可行恢复(可从单决策 + feasible 映射证明)作为承重指标,**绕开 OOD 闭环 + 不需要 use_map 路由**。

## 4. Suite-Cal parity(A 类,公允对手)

> ⚠️ **复现性披露(2026-06-30,E4 前置检查发现):下表的闭环 reach 数字不可稳定复现。** 后续在真实 Go2 上重跑同一 `o2_compliance_A`(同 seeds/monitor)得到 B1 ∈ {0.00(接 O1_A 之后), 0.67(孤立跑)},`o1_ice_A` B1 由 1.00 漂到 0.33 —— 均**复现不出**下表记录的 1.00。根因:复用 Isaac app 的物理残留(`reset(seed)` 未完全清除)+ B1 在 A 类上本就乱跳的误归因,使闭环结果由噪声主导而非 θ 主导(见 `A实验/E4.md` §4–5、`outputs/eval/e4/reconcile.json`)。**故下表数字应读作"某次运行下成立",不作承重证据;"公允对手"论点改由可复现的 B1 未整定 0.764 归因保真度 + E1 C2ST 上界承载(见 §6.3)。** 头号的**开环三行(固定快照,确定性)不受影响**。

6 个 A 类算子 × 3 reps,闭环 reach 成功率(某次运行;见上方复现性披露):

| 场景 | B1 | B5 | B2-FSM |
|---|---|---|---|
| **O1_mu_field_A**(轻冰) | **1.00** | **1.00** | 0.00 |
| **O2_compliance_A**(浅泥) | **1.00** | 0.00 | 0.00 |
| O5_payload_A / O6_push_A / O10_effort_decay_A / O11_obs_bias_A | 0.00 | 0.00 | 0.00 |
| **总体** | **0.333** | 0.167 | 0.000 |

`parity |B1−B5| = 0.167 ≤ 0.2 → PARITY`。**关键诚实读法:在可穿越的 A 类上 B1 ≥ B5**(轻冰:1.00=1.00,B1 匹配 agent;浅泥:1.00>0.00,B1 甚至超过)→ **B1 是公允强对手,绝非稻草人**;而 cause-blind 的 B2-FSM 在 O1_A 上也失败(它后退/绕行而非低速穿过)。四个全局算子 A 类场景(O5/O6/O10/O11_A)对**所有** agent(含 B5)都 0.00 —— 在这个"监视器触发→恢复"的闭环里它们不是干净可穿越的(恢复原语打断了到达),是已知局限(§6),不是 B1 的弱点。

## 5. 对论文的支撑

- **C1 二分法(正反两面闭合)**:负面 —— B1 在匹配对 O4 冲突案例归因 0.00 [0.00,0.20](纯本体盲,E1 C2ST 上界);正面 —— B5-conflict 1.00 [0.80,1.00](语义可解)。中间 —— B5-unshaped O4 0.27 [0.11,0.52](有视觉但没学会用)。
- **新论点(中间行)**:冲突消解是**学出来的**语义操作(O4 冲突案例 +0.73 净增益,0.27→1.00),不是数据覆盖副产品。"有视觉 ≠ 会用视觉。"
- **C3 公允对手**:B1 在未整定算子上 0.764 归因保真度(强归因器)+ E1 C2ST 上界,堵住"你赢了稻草人"。(原 Suite-Cal 闭环 parity 数字不可稳定复现 → 降级,见 §4 披露 / `A实验/E4.md`。)

## 6. 诚实的局限

1. **B5-unshaped 不是 chance,但在 O4 冲突案例上明显失败**:它在 O2 对照上几乎全对(0.87),所以总体归因 0.57 不是 chance —— 这正是"有视觉通道"的体现;但在 O4 冲突案例上只有 **0.27 [0.11, 0.52]**(把 n 从 5 加到 15 后,早先 n=5 的 0.60 被证实是小样本噪声,真实水平更低)。因此**头号必须用 O4 冲突列、且用归因门控的「正确恢复率」,而非总体或 ungated 可行恢复率**(后者对 B1 是虚高的 0.567)。承重对比 **O4 冲突案例 0.00 < 0.27 < 1.00**,按 Wilson CI 显著单调。
2. **闭环匹配-O4 对 B5 OOD**:故三行用**开环单原语**(避开 OOD 闭环 + 路由)。物理"推过被弹飞/后退脱困"的闭环版受 #49 匹配-vs-陷阱张力限制(E1 G1/G2 未找到既匹配又陷阱的 preset,fallback),未纳入头号结果。
3. **Suite-Cal 闭环 reach 不可稳定复现(2026-06-30 修订,重要)。** E4 前置检查(`A实验/E4.md`)发现:同一 `o2_compliance_A` 重跑得 B1 ∈ {0.00, 0.67}、`o1_ice_A` B1 1.00→0.33,均复现不出 §4 记录的 1.00 —— 复用 Isaac app 的物理残留 + B1 在 A 类上乱跳的误归因使闭环由噪声主导。⇒ **§4 的具体闭环数字降级为"某次运行下成立、口径不稳、需修后重跑";"公允对手"论点改由两条可复现证据承载:(i) B1 在未整定算子上的 0.764 归因保真度(确定);(ii) E1 的 C2ST 上界(确定、不依赖此闭环)。** 此外四个全局算子 A 类(O5/O6/O10/O11)对所有 agent 都 0.00(恢复原语打断到达 / A 类 θ 偏难,如 O10_A floor=0.4 已过基策略物理极限)。修闭环口径(monitor 工作点 A/B-aware + 确定性 + 重定 O10 的 A 类 θ)是 E4 的前置工作,详见 `A实验/E4.md` §6。**头号开环三行(固定快照)确定、不受影响。**
4. **样本量**:头号开环三行的 matched_eval 已扩到 **n=30(15 O4 + 15 O2)**,附 Wilson 95% CI,O4 三行 CI 已**显著分开**(0.27 上界 0.52 < 1.00 下界 0.80)。Suite-Cal(闭环)只有 3 reps 且经 §6.3 判定不可稳定复现 —— 不仅是样本量问题,需先修口径(`A实验/E4.md` §6)再重跑。
5. **#50(待人签字)**:#49 闭环陷阱 preset 未达成(matched-vs-trap 张力);故 recovery 物理版降级为开环单原语 + feasible-set consequence。spec §8.1 P4 改写仍是 human call(同 E1)。
